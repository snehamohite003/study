1. Introduction to DNS

DNS stands for Domain Name System.

It is the system that translates human-readable domain names into machine-usable IP addresses.

Examples

  • google.com
  • amazon.com
  • api.github.com

These names are converted into IP addresses such as:

  • 142.250.183.14 (IPv4)
  • 2607:f8b0:4004:c1b::64 (IPv6)

Simple Definition

DNS is the phonebook of the internet.

Humans remember names easily, while computers communicate using IP addresses. DNS bridges this gap.

2. Why DNS Exists

Without DNS, users would need to remember the IP address of every website or service they wanted to access.

Problems Without DNS

  • IP addresses are difficult to memorize
  • Server IPs can change over time
  • Infrastructure migrations would break access
  • Load balancing would be harder
  • Failover would be more difficult
  • Large-scale internet communication would become unmanageable

DNS Solves These Problems By Providing

  • Name-to-IP mapping
  • Service discovery
  • Email routing
  • Load distribution
  • Fault tolerance
  • Location abstraction

DNS allows users and applications to rely on a stable name, while the underlying infrastructure can change transparently.

3. DNS Namespace and Hierarchy

DNS is organized as a hierarchical tree structure.

Example Hierarchy

  • .
    • com
      • example.com
      • google.com
    • org
    • net

How a Domain Name Is Read

Take this domain:

api.dev.example.com

It is interpreted from right to left:

  • . → root
  • com → top-level domain (TLD)
  • example → second-level domain
  • dev → subdomain
  • api → host label

Why Hierarchy Matters

  • Scalable
  • Distributed
  • Decentralized
  • Easy to delegate
  • Operationally manageable

No single DNS server needs to know everything. Each layer only needs to know the next responsible layer.

4. Domains and Zones

Although often used interchangeably, domain and zone are not exactly the same.

4.1 Domain

A domain is a logical part of the DNS namespace.

Example: example.com

4.2 Zone

A zone is an administrative portion of the namespace managed by a specific set of authoritative DNS servers.

Important Difference

  • A domain is a naming concept
  • A zone is a management concept

Example

  • example.com may be one zone
  • shop.example.com may be delegated and managed separately as another zone

Why Zones Matter

  • Independent administration
  • Delegation to different teams
  • Better scalability
  • Separation of responsibility

5. Core DNS Components

5.1 Stub Resolver

A stub resolver is the lightweight DNS client present on a user machine or operating system.

Responsibilities

  • Receives lookup requests from applications
  • Sends DNS query to a recursive resolver
  • Returns the answer back to the application

A stub resolver usually does not perform full recursive resolution itself.

5.2 Recursive Resolver

A recursive resolver performs the full DNS lookup on behalf of the client.

Examples

  • ISP DNS servers
  • Google Public DNS (8.8.8.8)
  • Cloudflare DNS (1.1.1.1)

Responsibilities

  • Accept recursive queries from clients
  • Check its cache
  • If needed, query root, TLD, and authoritative servers
  • Return the final answer
  • Cache the response for future use

5.3 Root Name Servers

Root name servers sit at the top of the DNS hierarchy.

They do not usually know the final IP address of a domain. Instead, they know which servers manage each top-level domain.

“I do not know the final answer, but ask the .com TLD servers.”

There are 13 logical root server names, but they are distributed globally using anycast.

5.4 TLD Name Servers

TLD stands for Top-Level Domain.

Examples of TLDs

  • .com
  • .org
  • .net
  • .in

TLD servers know which authoritative name servers are responsible for domains under that TLD.

5.5 Authoritative Name Servers

An authoritative name server is the official source of DNS data for a zone.

Example

  • www.example.com -> 93.184.216.34
  • mail.example.com -> 192.0.2.20

This is the source of truth for DNS data.

6. DNS Record Types

6.1 A Record

Maps a hostname to an IPv4 address.

Example: www.example.com -> 93.184.216.34

6.2 AAAA Record

Maps a hostname to an IPv6 address.

Example: www.example.com -> 2606:2800:220:1:248:1893:25c8:1946

6.3 CNAME Record

Maps one hostname to another hostname.

Example: www.example.com -> app.example.com

6.4 MX Record

Specifies mail servers for a domain.

Example: example.com -> 10 mail.example.com

The number indicates priority. Lower value means higher priority.

6.5 NS Record

Specifies which authoritative nameservers manage a zone.

Example: example.com -> ns1.provider.net

6.6 TXT Record

Stores arbitrary text data.

Common Uses

  • SPF
  • DKIM
  • DMARC
  • Domain ownership verification

6.7 SOA Record

SOA stands for Start of Authority.

It contains metadata for the zone, such as:

  • Primary nameserver
  • Serial number
  • Refresh interval
  • Retry interval
  • Expire time
  • Negative caching TTL

6.8 PTR Record

Used for reverse DNS, mapping an IP address back to a hostname.

6.9 SRV Record

Specifies service-related information such as:

  • Service name
  • Protocol
  • Target host
  • Port
  • Priority and weight

6.10 CAA Record

Specifies which certificate authorities are allowed to issue certificates for the domain.

7. How DNS Resolution Works

Suppose a user opens: www.example.com

  1. Browser checks its local DNS cache
  2. Operating system checks DNS cache
  3. Hosts file is checked
  4. Stub resolver queries recursive resolver
  5. Recursive resolver checks its own cache
  6. If not cached, it asks a root server
  7. Root server refers it to TLD server
  8. TLD server refers it to authoritative server
  9. Authoritative server returns final answer
  10. Recursive resolver caches the result
  11. Client receives the IP and connects

8. Recursive vs Iterative Queries

8.1 Recursive Query

“Give me the final answer.”

The client sends this to the recursive resolver.

The resolver must return:

  • Final answer
  • Failure
  • NXDOMAIN

8.2 Iterative Query

“Give me the best information you have, and if you do not know the final answer, tell me who to ask next.”

The recursive resolver sends iterative queries to root, TLD, and authoritative servers.

Typical real-world flow:

  • Client → Recursive Resolver = recursive query
  • Recursive Resolver → Other DNS Servers = iterative queries

9. Stub Resolver vs Recursive Resolver vs Authoritative Server

  • Stub Resolver: Runs on client device, sends DNS request
  • Recursive Resolver: Performs the full lookup and caches responses
  • Authoritative Server: Holds official DNS records

Memory Trick: Stub resolver asks, recursive resolver finds, authoritative server knows.

10. Caching and TTL

Caching is one of the most important features in DNS. It reduces latency and decreases infrastructure load.

10.1 What Is TTL?

TTL stands for Time To Live.

It tells caches how long a DNS response can be stored.

Example: TTL = 300 seconds means the answer may be reused for 5 minutes.

10.2 Benefits of Caching

  • Faster responses
  • Reduced latency
  • Lower DNS infrastructure load
  • Better scalability

10.3 TTL Tradeoff

High TTL

  • Fewer DNS lookups
  • Better performance
  • Lower server load
  • Slower updates
  • Slower failover

Low TTL

  • Faster DNS changes
  • Better for failover
  • More dynamic routing
  • More DNS traffic
  • Higher resolver load

11. Negative Caching

DNS also caches failed lookups.

  • Domain does not exist
  • Requested record type does not exist

This prevents repeated useless lookups and reduces load on DNS servers.

12. DNS Load Balancing

DNS can distribute traffic by returning multiple IPs for the same domain.

Example:

  • 10.0.0.1
  • 10.0.0.2
  • 10.0.0.3

Common Strategies

  • Round-robin DNS
  • Weighted routing
  • Geo-based routing
  • Latency-based routing
  • Failover routing

Important limitation: DNS is not precise real-time load balancing because clients and resolvers cache responses.

13. Reverse DNS

Normally DNS maps Hostname → IP. Reverse DNS maps IP → Hostname.

Uses:

  • in-addr.arpa for IPv4
  • ip6.arpa for IPv6

Common uses:

  • Email validation
  • Logging
  • Diagnostics
  • Security analysis

14. Zone Transfers

Authoritative DNS uses multiple servers for redundancy. Zone transfers keep them synchronized.

  • AXFR = full zone transfer
  • IXFR = incremental zone transfer

Zone transfers typically use TCP.

15. UDP vs TCP in DNS

Most DNS traffic uses UDP port 53.

Why UDP Is Common

  • Lightweight
  • Low overhead
  • Fast for small exchanges

When TCP Is Used

  • Response is too large
  • Truncation occurs
  • DNSSEC increases response size
  • Zone transfers are needed

16. DNSSEC

DNSSEC stands for Domain Name System Security Extensions.

It adds verification to DNS responses.

What DNSSEC Provides

  • Authenticity
  • Integrity

What DNSSEC Does Not Provide

  • Encryption
  • Privacy

Important Records

  • DNSKEY
  • RRSIG
  • DS
  • NSEC / NSEC3

17. DNS Privacy: DoH, DoT, and DoQ

Traditional DNS traffic is often unencrypted.

Modern Privacy Enhancements

  • DoH = DNS over HTTPS
  • DoT = DNS over TLS
  • DoQ = DNS over QUIC

Benefits include improved privacy and reduced snooping.

18. Delegation and Glue Records

18.1 Delegation

Delegation means a parent zone passes responsibility for a subdomain to another set of nameservers.

18.2 Glue Records

Glue records are address records included by the parent zone to help resolvers reach delegated nameservers.

They prevent circular dependency during resolution.

19. DNS Failure Scenarios in System Design

  • High TTL delays failover
  • Low TTL increases query load
  • Authoritative server outage
  • Misconfigured NS records
  • Missing or stale glue records
  • DNSSEC misconfiguration
  • Stale caches during migration

20. Interview-Level Important DNS Concepts

  1. Hierarchical Resolution — DNS distributes responsibility across root, TLD, and authoritative layers.
  2. Recursive vs Iterative Queries — Clients ask recursively; resolvers walk iteratively.
  3. Caching and TTL — Improves performance while affecting freshness.
  4. Authoritative vs Recursive Servers — Source of truth vs lookup helper.
  5. Record Types — Support IP mapping, aliasing, mail, verification, and more.
  6. DNS Load Balancing — Useful for traffic steering but limited by caching.
  7. DNSSEC — Adds authenticity and integrity.
  8. UDP vs TCP — UDP for most lookups, TCP for large responses and transfers.
  9. Reverse DNS — Maps IP back to hostname.
  10. Delegation and Glue — Supports distributed ownership and resolver reachability.

21. End-to-End Example

Suppose the client wants to resolve www.shop.example.com.

  1. Client asks recursive resolver
  2. Recursive resolver asks root server
  3. Root refers to .com
  4. Resolver asks .com
  5. .com refers to example.com authoritative servers
  6. Resolver asks example.com
  7. If shop.example.com is delegated, NS records and glue are returned
  8. Resolver asks authoritative server for shop.example.com
  9. Final A or AAAA record is returned
  10. Resolver caches answer based on TTL
  11. Client receives IP and connects
